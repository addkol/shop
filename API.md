# HTTP-интерфейсы проекта

В текущей версии нет публичного REST API каталога или заказов. Магазин использует серверные Django-страницы, формы, session authentication и CSRF-защиту. Нельзя интегрироваться с адресами `/api/products/` или ожидать JSON от форм магазина — таких маршрутов нет.

## Служебный endpoint

### `GET /health/`

Проверяет доступность приложения и соединение с базой.

Успешный ответ:

```json
{"status": "ok"}
```

При недоступной базе возвращается HTTP 503:

```json
{"status": "unavailable"}
```

## Webhook Finik

### `POST /webhook/finik/`

Единственный внешний JSON endpoint. CSRF для него отключён, но запрос принимается только после проверки RSA-SHA256 подписи и свежести `x-api-timestamp`.

Обязательные данные события:

- `transactionId` или `id` — уникальный ID события;
- `status` — `success`, `succeeded` или `failed`;
- `amount` — сумма платежа;
- `fields.paymentId` — ID платежа заказа.

Обязательные заголовки:

- `signature`;
- `x-api-timestamp`;
- остальные `x-api-*`, включённые Finik в подписываемый запрос.

Обработчик сверяет сумму заказа, блокирует запись транзакцией и сохраняет `PaymentEvent`. Повтор события с тем же ID безопасен. Поздняя оплата отменённого заказа переводится в статус «Требуется возврат», а `failed` после успешной оплаты не отменяет заказ.

Типовые ответы:

- HTTP 200 — событие обработано или уже было обработано;
- HTTP 400 — неверные поля, сумма или статус;
- HTTP 401 — подпись или timestamp недействительны;
- HTTP 404 — платёж не связан с заказом;
- HTTP 503 — публичный ключ webhook не настроен.

## Внутренние формы

HTML-формы регистрации, входа, корзины, checkout, отмены и отзывов требуют корректный CSRF token. Маршруты, методы и требования авторизации перечислены в `shop/urls.py`, `accounts/urls.py` и `payment/urls.py`.

Если потребуется мобильное приложение или внешняя интеграция, REST API нужно проектировать отдельно: с версионированием, сериализаторами, token authentication, permissions, throttling и OpenAPI-схемой.
